# Review Platform Guest API 1.1.0

Опциональная поставка с постоянной браузерной сессией. [openapi.yaml](openapi.yaml) задаёт границу guest-v1; [CHANGELOG.md](CHANGELOG.md) ведёт её изменения. Основание: [ADR-0002](../../../docs/adr/0002-optional-guest-workspaces.md), [срез 008](../../../specs/008-guest-access/spec.md).

## Отношение к trusted v1

Guest-v1 включается оператором через `REVIEW_GUEST_ACCESS=true`. Пути `/v1/...`, предметные DTO и skill JSON сохраняются из [trusted v1](../v1/README.md). Новая семантика bootstrap, cookie и ошибок доступа описана отдельной версией; canonical no-auth `v1/openapi.yaml` остаётся неизменённым. При выключенном гостевом режиме действует trusted deployment.

Файл OpenAPI создаёт [build_guest_contract.py](../../../tools/contracts/build_guest_contract.py) из trusted-v1 baseline. Изменения гостевой границы вносятся в генератор, предметные дополнения — в trusted-v1; результат проверяется регенерацией. Ручная правка generated OpenAPI не является источником истины. HTTP-примеры предметных данных остаются в [v1/examples/http](../v1/examples/http/).

## Браузерная сессия

1. `GET /v1/bootstrap` без действующей cookie создаёт отдельные workspace и actor, возвращает обычный Bootstrap DTO и cookie `review_guest`.
2. Cookie — непрозрачный случайный credential с `HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=2592000`. В PostgreSQL хранится SHA-256 credential вместе с deployment, organization, workspace, actor и сроками.
3. Запрос с действующей cookie продлевает сессию на 30 дней и возвращает `Set-Cookie`. Перезапуск API не меняет связь с сохранёнными данными.
4. Все workspace-операции требуют действующую сессию. Middleware выбирает workspace/actor по серверной записи; ID из URL не даёт доступа к другому гостю или исходному private workspace.
5. Ответы сессии и данных используют `Cache-Control: no-store`. Browser cross-origin запросы отклоняются; сервис предназначен для работы через HTTPS с одного origin.

Без cookie, после её удаления или после 30 дней без использования bootstrap создаёт новое пустое пространство. Прежние данные остаются на сервере; восстановления связи через email, другой браузер или общий код нет. Пользователь может вернуться к данным, пока сохраняется действующая cookie того же браузера.

## Хранение и лимиты

Документы, извлечение, проверки, диалоги, решения и пользовательские профили сохраняются в PostgreSQL/POSIX. Срок сессии не является сроком удаления данных; автоматическая очистка в эту версию не входит.

| Ограничение по умолчанию | Значение | Область |
| --- | --- | --- |
| Один файл | 50 MiB | Наследуется из runtime upload budget; фактическое значение приходит в Bootstrap |
| Исходные загрузки одного гостя | 200 MiB и 20 документов | Основные документы и контекст суммарно |
| Исходные загрузки всех гостей | 1 GiB | Зарегистрированные гостевые пространства организации, включая истёкшие сессии |
| Резерв свободного диска | 3 GiB | Перед загрузкой дополнительно учитывается тройной размер входа |

Гостевые квоты учитывают сохранённые документы и резервы принятых загрузок. Проверка и резервирование выполняются короткой общей транзакцией; разбор и сохранение разных загрузок идут параллельно. Квоты ограничивают исходные загруженные байты и число документов; размеры PostgreSQL, извлечённых фрагментов, отчётов и журналов не входят в лимит 1 GiB. При проверке свободного диска дополнительно учитывается тройной размер всех активных резервов и нового файла. Чтение уже сохранённых данных остаётся доступным при отказе новой загрузки. Настройка оператора: [deployment](../../../docs/operations/deployment.md).

Каждая новая версия в `document-families/{familyId}/versions` учитывается как исходная загрузка в тех же квотах. Повтор запроса с прежним `Idempotency-Key` возвращает сохранённую версию без повторного начисления. Семейство, версия, сравнение, ссылки на прежние замечания и PDF доступны только своей гостевой сессии.

## Ошибки и совместимость

| HTTP / code | Условие |
| --- | --- |
| `401 guest_session_required` | Workspace-операция без действующей cookie; сначала требуется bootstrap |
| `403 cross_origin_forbidden` | Запрос браузера с другого origin |
| `404 not_found` | Чужой workspace или ресурс, включая foreign ID внутри собственного workspace |
| `413 payload_too_large` / `guest_storage_limit` | Превышен размер файла или личная квота загрузок |
| `503 storage_unavailable` | Исчерпан общий бюджет загрузок или резерв диска |

Собственный ещё не опубликованный отчёт сохраняет `409 report_unavailable`. Revision conflicts, идемпотентность и неизменяемость отчёта сохраняют семантику trusted v1. Ответы навыка и DTO модели не содержат cookie или provider credentials.

Основной интерфейс доступен гостям. Подготовленный `/demo` с приватным runtime-пакетом остаётся за gateway-допуском. Если gateway настроен на публичный режим, а API его не подтвердил, gateway прекращает доступ к приложению.
