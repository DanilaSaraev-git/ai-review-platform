# ADR-0001: Contract-first модульный монолит

- Статус: accepted
- Дата: 2026-09-04
- Основание: зафиксированный архитектурный baseline целевой платформы
- Дополнение: [ADR-0002](0002-optional-guest-workspaces.md) заменяет ограничение одного workspace только для опционального guest-v1; trusted-v1 baseline сохраняется.

## Контекст

Два разработчика начинают параллельно: коллега делает web, автор продукта — backend, review engine, CLI и skills. Продукт должен пройти три стадии — локальный PoC, самостоятельный движок и self-hosted сервис — без трёх расходящихся реализаций предметной логики. При этом локальный skill не должен зависеть от запущенного HTTP-сервера, а будущий web не должен читать внутренние файлы PoC или skill runtime.

Продуктовые гипотезы ещё не подтверждены, поэтому раннее разделение на микросервисы и привязка к одному LLM или хранилищу создадут больше стоимости, чем проверенной пользы.

## Решение

Развивать один модульный Python-монолит с отдельными процессами API и worker из одной кодовой базы.

- `Review Application` является глубоким прикладным интерфейсом для загрузки, запуска, отчёта, диалога и решения человека.
- React SPA вызывает его через design-first HTTP OpenAPI v1.
- CLI и локальный AI-skill вызывают тот же Python application/core напрямую, без HTTP.
- `Review Engine` скрывает разбиение больших документов, вызовы модели, retries, synthesis, дедупликацию и семантическую валидацию.
- Навык является версионированным декларативным пакетом. Граница engine ↔ skill выражена отдельными JSON Schema для review и finding dialogue.
- LLM, очередь, артефакты, parser и repositories находятся за узкими внутренними портами только там, где предусмотрено более одной реальной реализации.
- Отчёт и найденные замечания неизменяемы. Диалог, предложение модели и решение человека хранятся отдельно.
- Первый deployment содержит одну configured organization, один workspace и одного actor для атрибуции. Их ID остаются namespace и будущим миграционным швом, но не заявляются как механизм доступа.
- HTTP v1 не содержит authentication, accounts, membership, roles или authorization; deployment предназначен только для доверенного контура.

Первый стек: React + TypeScript + Vite; FastAPI/Pydantic/SQLAlchemy; PostgreSQL; Procrastinate за `JobQueue` с transactional outbox; POSIX и optional S3 реализации `ArtifactStore`. Полный список и политика версий — в [плане](../../specs/002-target-review-platform/plan.md) и [исследовании](../../specs/002-target-review-platform/research.md).

## Последствия

Положительные:

- web и backend могут компилироваться и тестироваться независимо от одного контрактного коммита;
- локальный skill сохраняет offline/self-contained сценарий и общую семантику с сервисом;
- фоновые задания и тяжёлая обработка масштабируются отдельными worker-процессами без изменения HTTP;
- конкретные провайдеры инфраструктуры заменяются адаптерами, а namespace IDs сохраняют возможность отдельно спроектировать multi-organization версию в будущем.

Издержки:

- канонический OpenAPI, экспорт FastAPI, JSON Schema и примеры нужно синхронизировать в CI;
- API и worker обязаны проверять одинаковый configured organization/workspace namespace и обеспечивать идемпотентность at-least-once заданий;
- очередь за общей PostgreSQL требует outbox, dispatcher, восстановления stalled jobs и отдельных миграций;
- монолит требует явных границ модулей, иначе общая кодовая база превратится в неуправляемую связанность.

## Рассмотренные альтернативы

- **Next.js как full-stack framework**: не выбран, потому что серверная предметная логика и worker всё равно остаются в Python; публичный marketing/SSR-сайт при необходимости может быть отдельным приложением.
- **Angular**: технически пригоден, но для небольшого первого web-среза даёт больше обязательной структуры и не создаёт преимущества на выбранной границе OpenAPI. Решение можно пересмотреть, если команда стандартизирована на Angular.
- **Микросервисы с первого дня**: отложены до измеренного ограничения по нагрузке, отказам или независимому развёртыванию.
- **Skill вызывает backend API**: отвергнуто, потому что ломает локальный режим и делает PoC зависимым от сервера.
- **Общая библиотека DTO для Python и TypeScript**: отвергнута; межъязыковым источником истины служат OpenAPI и JSON Schema.
- **OIDC, аккаунты, роли и multi-organization isolation в первом срезе**: исключены прямым решением пользователя. Их нельзя добавлять как «инфраструктурную деталь»; возвращение требует отдельной спецификации и ADR.

## Когда пересмотреть

Решение пересматривается при измеренной необходимости независимо масштабировать или выпускать extraction/model execution, при появлении обязательного Kubernetes/enterprise-стандарта заказчика либо подтверждённой потребности в недоверенном или multi-organization доступе. Изменение публичной семантики требует новой версии контракта, а не скрытой замены внутри v1.
