# Implementation Plan: Веб-интерфейс AI Review v1

**Branch**: `codex/005-web-review-ui` | **Date**: 2026-09-04 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/005-web-review-ui/spec.md`

## Summary

Аналитик данных самостоятельно загружает готовое ТЗ, запускает фоновое ревью, разбирает адресные замечания в неизменяемом отчёте, уточняет одно выбранное замечание диалогом и сохраняет собственное решение по нему. Реализуется только web-контур в `apps/web/`.

Технический подход: одностраничное приложение на React и Vite, которое работает исключительно с HTTP-ресурсами [контракта Review Platform v1](../../contracts/review-platform/v1/README.md). Типы, fetch-клиент, query hooks и MSW handlers генерируются Orval из зафиксированного `openapi.yaml` — ручных копий DTO нет. Серверное состояние держит TanStack Query; фоновые запуски и ходы диалога наблюдаются автоматическим опросом с интервалом, обеспечивающим видимость изменения не позднее 2 секунд. До готовности backend приложение работает против MSW, отвечающего каноническими примерами из `contracts/review-platform/v1/examples/http/`; переключение на реальный API меняет только транспорт, но не DTO и не компоненты.

## Technical Context

**Language/Version**: TypeScript 6.0.3, Node.js 24.20.0 LTS

**Primary Dependencies**:

| Пакет | Версия | Назначение |
| --- | --- | --- |
| React | 19.2.8 | UI-слой |
| Vite | 8.2.2 | Сборка и dev-сервер |
| React Router | 7.18.3 | Маршрутизация |
| TanStack Query | 5.102.8 | Серверное состояние, опрос, инвалидация |
| Orval | 8.28.1 | Генерация клиента, query hooks и MSW handlers из `openapi.yaml` |
| MSW | 2.15.0 | Моки по `examples/http/` для работы без backend |
| Tailwind CSS | 4 (точный patch фиксируется при установке) | Стилизация |
| Radix UI primitives | фиксируется при установке | Доступные примитивы диалогов, меню, полей |
| React Hook Form + Zod | фиксируется при установке | Формы и валидация ввода |
| PDF.js | фиксируется при установке | Просмотр PDF и переход к процитированному фрагменту |

Redux не добавляется: серверное состояние покрывает TanStack Query, локальное — состояние компонента и параметры маршрута.

**Storage**: N/A на стороне web. Единственное локальное хранение — черновики ввода аналитика (обоснование решения, текст вопроса) в памяти вкладки на время разрешения конфликта ревизии; постоянного клиентского хранилища нет.

**Testing**: Vitest + Testing Library — модульные и компонентные тесты; Playwright — E2E, включая режим против MSW.

**Target Platform**: современные desktop-браузеры; мобильная раскладка вне объёма v1.

**Project Type**: отдельное веб-приложение (frontend-only) в `apps/web/`. Backend, worker и engine реализует другой контур по тому же `openapi.yaml` и в этот план не входят.

**Performance Goals**:

- Изменение состояния запуска и завершение хода диалога видимы аналитику не позднее 2 секунд (SC-012).
- Запуск, не менявший состояние 15 минут, сопровождается предупреждением и длительностью (SC-013).
- Отчёт до 500 замечаний (потолок контракта) открывается и остаётся пригодным для разбора; числовая цель по объёму намеренно не установлена (спецификация, раздел Assumptions).

**Constraints**:

- Контракт v1 заморожен. Изменение публичного HTTP вносится отдельным PR в `codex/002-target-review-platform`, а не правкой в web-ветке.
- DTO вручную не копируются — только сгенерированные Orval артефакты.
- Сгенерированные файлы не коммитятся; `package-lock.json` коммитится. Пакетный менеджер — npm.
- Нет экранов входа, регистрации, ролей и выбора рабочего пространства.
- Отчёт неизменяем: решения и диалог не меняют его тело и ETag.
- Материалы client не используются в фикстурах и тестах интерфейса — только синтетические данные.
- Все зависимости фиксируются точными версиями, без диапазонов.

**Scale/Scope**: одно настроенное рабочее пространство, один доверенный actor, один аналитик за раз. Пять функциональных областей по User Story, ориентировочно 6 маршрутов и 4 фоновых потока наблюдения (список запусков, текущий запуск, состояния замечаний, диалог замечания).

### Source Code (repository root)

Создаётся только `apps/web/`. Каталоги backend-контура упомянуты для полноты владения и этим планом не создаются.

```text
apps/web/
├── package.json                  # точные версии, без диапазонов
├── package-lock.json             # коммитится
├── tsconfig.json
├── vite.config.ts
├── orval.config.ts               # источник: contracts/review-platform/v1/openapi.yaml
├── vitest.config.ts

├── index.html

│   ├── app/                      # провайдеры, маршруты, каркас страницы
│   │   ├── router.tsx
│   │   ├── providers.tsx         # QueryClient, обработка Problem-ответов
│   │   └── layout/
│   ├── api/
│   │   ├── generated/            # Orval: типы, client, query hooks, MSW handlers (не коммитится)

│   ├── components/
│   │   ├── ui/                   # обёртки над Radix primitives
│   │   └── document-viewer/      # PDF.js и текстовый просмотр, подсветка фрагмента
```

**Structure Decision**: выбрана раскладка «frontend + backend» из шаблона, но в рамках этой фичи создаётся только frontend-часть — `apps/web/`. Это соответствует принципу VII: backend и engine принадлежат другому контуру и разрабатываются параллельно от того же контрактного тега. Внутри `src/features/` каталоги повторяют User Story спецификации, поэтому каждая история реализуется и проверяется независимо.
