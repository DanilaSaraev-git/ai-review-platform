# Контракт маршрутов приложения

**Дата**: 2026-09-04. Основание: [спецификация](../spec.md), [план](../plan.md).

`workspaceId` в маршрутах не участвует: он приходит из `GET /v1/bootstrap` и подставляется в HTTP-запросы приложением. Это прямое следствие принципа IV — аналитик не выбирает рабочее пространство и не вводит его идентификатор (FR-002).

## Карта маршрутов

| Маршрут | Экран | Основные данные | User Story |
| --- | --- | --- | --- |
| `/` | Список запусков и точка входа | `GET /v1/bootstrap`, `GET .../review-runs` | US1 |
| `/new` | Подготовка проверки | документы, профили проверки и модели, лимиты | US1, US5 |
| `/runs/:runId` | Состояние запуска | `GET .../review-runs/{runId}` | US1 |
| `/runs/:runId/report` | Отчёт и список замечаний | отчёт, состояния замечаний | US2 |
| `/runs/:runId/report/findings/:findingId` | Замечание, фрагмент документа, решение | отчёт, состояние замечания, содержимое документа | US2, US3 |
| `/runs/:runId/report/findings/:findingId/dialogue` | Диалог по замечанию | диалог замечания | US4 |

## Правила навигации

- Каждый маршрут открывается по прямой ссылке и восстанавливает своё состояние после обновления страницы. Выбранное замечание — часть URL, а не только состояние компонента: аналитик возвращается к разбору там, где остановился (US1-8).
- `/runs/:runId` — единственная точка наблюдения за фоновым запуском. При достижении `completed` интерфейс предлагает перейти к отчёту, но не выполняет переход сам: аналитик может смотреть на другой экран, и принудительная навигация сбила бы его.
- Переход на `/runs/:runId/report` при незавершённом или неуспешном запуске не показывает пустой отчёт: экран объясняет, что отчёта нет, и возвращает к состоянию запуска (FR-018, US2-7).
- Маршрут диалога вложен в маршрут замечания: диалог всегда относится к одному конкретному замечанию и не превращается в отдельный чат (FR-030).
- Неизвестный `runId` или `findingId`, а также идентификатор, не принадлежащий настроенному рабочему пространству, показывают обычное «не найдено» без упоминания прав доступа (FR-003, US2-8).

## Соответствие маршрутов операциям контракта

| Маршрут | Операции |
| --- | --- |
| `/` | `getBootstrap`, `listReviewRuns` |
| `/new` | `uploadDocument`, `getDocument`, `listReviewProfiles`, `listModelProfiles`, `createReviewRun` |
| `/runs/:runId` | `getReviewRun` |
| `/runs/:runId/report` | `getReviewReport`, `listFindingStates` |
| `.../findings/:findingId` | `getReviewReport`, `listFindingStates`, `downloadDocument`, `putFindingDecision` |
| `.../findings/:findingId/dialogue` | `getFindingDialogue`, `createFindingDialogueTurn`, `retryFindingDialogueTurn` |

Операция `cancelReviewRun` контрактом предусмотрена, но в v1 из интерфейса не вызывается (раздел Out of Scope спецификации); состояние `cancelled`, полученное извне, отображается корректно. Операция `createReviewProfile` в v1 не используется.

## Клавиатура и фокус

- Все переходы выполнимы с клавиатуры; ссылки остаются ссылками и открываются в новой вкладке штатными средствами браузера (FR-041).
- При переходе на маршрут замечания фокус переводится на его заголовок, при открытии диалога — на поле ввода вопроса, при конфликте ревизии — на область с актуальным значением (FR-042, R-12).
