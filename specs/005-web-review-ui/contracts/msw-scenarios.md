# Контракт сценариев моков

**Дата**: 2026-09-04. Основание: принципы III и VI раздела [«Принципы реализации»](../../../AGENTS.md), [examples/http](../../../contracts/review-platform/v1/examples/http/README.md).

Сценарии позволяют проверять web без backend и воспроизводить негативные случаи спецификации. Прикладной код о существовании моков не знает: сценарий выбирается переменной окружения при запуске dev-сервера и параметром запуска Playwright, а подмена происходит на сетевом слое (принцип III).

## Источник данных

Ответы берутся из канонических примеров `contracts/review-platform/v1/examples/http/`. Они синтетические и не содержат материалов client. Синтетические файлы документов для загрузки создаются в `apps/web/src/mocks/fixtures/`. Импорт чего-либо из `client-materials/` в фикстуры, тесты и демонстрации запрещён (принцип VI, FR-038).

## Именованные сценарии

| Сценарий | Что воспроизводит | Опорные примеры | Проверяемые требования |
| --- | --- | --- | --- |
| `happy-path` | очередь → работа → успешное завершение → отчёт → один ход диалога → сохранённое решение | `bootstrap`, `document`, `profiles`, `model-profiles`, `review-run.queued`, `review-run.completed`, `report`, `finding-states`, `dialogue.open`, `decision` | US1, US2, US3, US4 |
| `run-failed` | неудачное завершение с причиной и без публикации отчёта | `review-run.failed` | FR-015, US1-6 |
| `report-partial` | частичный отчёт при недоступном контекстном источнике | `report.partial` | FR-022, US5-4 |
| `dialogue-generating` | ход в процессе генерации, отправка следующего недоступна | `dialogue.generating` | FR-031, FR-032, SC-008 |
| `dialogue-failed` | ход завершился ошибкой, доступен повтор | `dialogue.failed` | FR-035 |
| `decision-conflict` | сохранение решения поверх устаревшей ревизии | `problem` (`revision_conflict`) | FR-027, SC-005 |
| `dialogue-conflict` | отправка хода поверх устаревшей ревизии диалога | `problem` (`revision_conflict`) | FR-036 |
| `not-found` | идентификатор вне настроенного рабочего пространства | `problem` со `status: 404` | FR-003, US2-8 |
| `document-extraction-failed` | документ, у которого извлечение текста не удалось | производный от `document` с `extraction_state: failed` | FR-040, US1-9 |
| `empty-report` | успешный запуск без замечаний | производный от `report` с пустым `findings` | FR-023, US2-5 |
| `run-stalled` | запуск без смены состояния дольше 15 минут | `review-run.queued` с неизменным состоянием | FR-039, SC-013 |
| `context-partial` | недоступный контекстный источник даёт частичный отчёт, а не неудачный запуск | `report.partial` | FR-022, US5-4 |

Производные фикстуры строятся из канонических примеров изменением отдельных полей и остаются синтетическими.

## Правила

1. Сценарий определяет только ответы сетевого слоя. Компоненты и hooks не содержат ветвлений по источнику данных.
2. Идемпотентность воспроизводится честно: повтор с тем же `Idempotency-Key` и тем же телом возвращает исходный результат, а не создаёт второй запуск (FR-012, SC-009).
3. Оптимистическая конкуренция воспроизводится честно: мутация с устаревшим `expected_revision` отвечает `409` с `code: revision_conflict`.
4. Смена состояний во времени моделируется последовательностью ответов на повторные запросы, чтобы проверялся реальный опрос, а не единичный снимок (SC-012).
5. Отчёт в моках неизменяем: сохранение решения и ход диалога не меняют ответ `getReviewReport` (FR-018, принцип V).
6. Переключение на реальный backend отключает worker моков и меняет базовый URL — и больше ничего.

## Использование в проверках

- Разработка: dev-сервер с выбранным сценарием.
- Компонентные тесты: тот же набор handlers через серверный вариант MSW.
- E2E: Playwright прогоняет `happy-path` и все негативные сценарии; после появления backend тот же smoke-сценарий выполняется против реального API без изменения кода приложения.
