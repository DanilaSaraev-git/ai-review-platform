# План реализации

Использовать текущую React/TypeScript/TanStack Query/Orval и FastAPI/PostgreSQL архитектуру 009. Макет не переносится как HTML: изменяются рабочие компоненты.

Совместимый контрактный срез: optional completion у ReviewCycle, endpoint завершения с expected_revision; optional attachment_document_ids у запроса/хода диалога. Генерировать клиент и static/guest contracts. Существующие JSONB snapshots хранят новые поля без миграции; старые записи трактуются как незавершённые.

В runtime проверять завершение по полному отчёту и эффективным решениям с учётом переноса, текущим исправлениям и ограничениям. Фиксировать actor/time и digest состояний; поздние изменения отменяют актуальность завершения. Вложения валидируются по workspace и лимитам, передаются в sources модельного диалога без изменения исходного отчёта.

UI: общий статус, панель истории, модальный запуск новой версии, список семейств, inline cycle entries, сохранение формы и ссылки на старые результаты. Использовать существующие компоненты карточки/диалога/загрузки.

Проверки: контрактная валидация, typecheck/build, целевые pytest и Vitest; короткий локальный smoke. Полный повтор несвязанных тестов не нужен.
