## Dependencies & Execution Order

`T001 → T002 → US1 → US2 → US3 → T013`; инструкция T012 может готовиться параллельно реализации после согласования интерфейса launcher. Внутри каждой истории сначала проверяется риск, затем соответствующее поведение, после чего выполняется независимый live сценарий. Для первого live старта initial probe из T010 подключается вместе с T004; его периодический lifecycle завершается в US3.

Изменения одного `tools/dev.py` выполняются последовательно. Отдельный агент может писать focused tests в `tests/test_dev_launcher.py`, когда интерфейс launcher определён; разные проверки в одном test-файле не редактируются параллельно.

## Parallel Examples

- US1: T003 (изолированные проверки startup) и T004 (реализация запуска) после T002; T005 ждёт обе задачи.
- US2: сценарии T006 можно готовить параллельно T007 при разделённом владении кодом и tests; T008 ждёт обе задачи.
- US3: T009 и T010 используют разные файлы; T011 ждёт обе задачи.
- T012 независим от runtime и может готовиться вместе с любой историей после фиксации команд.

## Implementation Strategy

Первый проверяемый результат — US1 с безопасной основой launcher. Полная передача пользователю требует всех трёх историй, сохранности данных и evidence. Реализация идёт в текущем техническом checkout; новая серверная выкладка и перенос клиентских материалов отсутствуют в объёме.
