# Data Model: документ и цикл ревью

## Persistent document

DocumentFamily принадлежит organization/workspace и содержит название, автора и время создания. DocumentVersion сохраняет прежний ID и исходник; членство даёт family ID и положительный последовательный номер. Пара family/number уникальна. Старые версии backfill как отдельные семьи v1; новые uploads по прежнему API создают новые семьи, upload version добавляет участника существующей семьи.

Run сохраняет прежний document_id и отдельную фиксированную baseline связь, nullable. База принадлежит той же семье и уже имела отчёт до создания текущего запуска.

## Review cycle

CycleSnapshot принадлежит запуску, содержит baseline, статус/ограничения, сквозные issue entries и revision. Issue хранит origin run/finding, последнее появление и текущее nullable появление. Отсутствие не удаляет issue. Связь с finding текущего запуска уникальна.

Состояния сравнения выражают новое/повторённое/сомнительное/не обнаруженное/не проверенное/вернувшееся замечание. Состояние исправления open/resolved независимо от HumanDecision. Только человек задаёт resolved с пояснением и может вернуть open. Возврат проблемы создаёт необходимость пересмотра.

Перенос решения хранит source run/finding и оригинальную оценку с actor/time. Не имитировать новое решение человека и не изменять прошлое. Текущая явная оценка приоритетнее перенесённой.

Ручное связывание/разъединение и исправление используют expected revision. Занятые one-to-one связи — conflict. Все изменения сохраняют actor/time/reason и audit history. Retry не удаляет ручной прогресс.

## Export snapshot

Снимок содержит generated_at, документ/версию, run/report, current finding states и cycle со всеми сохранёнными состояниями. Чтение PostgreSQL в одной согласованной транзакции; fixture под общей блокировкой. PDF содержит ровно эти данные, полные диалоги не включаются. Байты canonical report и его ETag не изменяются.
