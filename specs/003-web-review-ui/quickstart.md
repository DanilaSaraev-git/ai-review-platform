# Quickstart: проверка веб-интерфейса AI Review v1

**Дата**: 2026-09-04. **План**: [plan.md](plan.md). **Спецификация**: [spec.md](spec.md).

Документ описывает, как запустить интерфейс и убедиться, что фича работает. Реализация здесь не приводится — она в задачах и коде.

## Предусловия

- Node.js 24.20.0 LTS, npm.
- Репозиторий на ветке `codex/web-review-v1`, созданной от тега `review-platform-contract-v1.0.0`.
- Доступен файл контракта `contracts/review-platform/v1/openapi.yaml`.
- Backend не требуется: проверка выполняется против MSW.

## Установка и генерация клиента

```bash
cd apps/web
npm ci
npm run api:generate
```

Генерация обязательна перед сборкой, тестами и E2E: каталог `src/api/generated/` не хранится в репозитории (см. [contracts/orval.md](contracts/orval.md)). Если `npm run api:generate` даёт diff после повторного запуска — правился сгенерированный файл; исправление вносится в источник, а не в выход.

## Запуск против моков

```bash
npm run dev                                   # сценарий happy-path по умолчанию
MSW_SCENARIO=report-partial npm run dev       # частичный отчёт
MSW_SCENARIO=decision-conflict npm run dev    # конфликт ревизии решения
```

Перечень сценариев и их назначение — в [contracts/msw-scenarios.md](contracts/msw-scenarios.md).

## Smoke-сценарий

Общий для обоих контуров сценарий из [порядка параллельной разработки](../../architecture/parallel-development.md): bootstrap → загрузка документа → создание запуска → ожидание терминального состояния → неизменяемый отчёт → один ход диалога → сохранение решения.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Открыть `/` | видны название рабочего пространства, организация, действующее лицо и лимиты; ни одного экрана входа или выбора пространства |
| 2 | Перейти на `/new`, загрузить синтетический документ | показаны имя, формат, размер и состояние извлечения текста |
| 3 | Выбрать профиль проверки и профиль модели | недоступный профиль модели невыбираем и объясняет причину |
| 4 | Запустить проверку | создан один запуск, экран сразу показывает состояние «в очереди» |
| 5 | Наблюдать запуск | состояния сменяются без действий пользователя, изменение видно не позднее 2 секунд |
| 6 | Открыть отчёт после `completed` | видны сводка, замечания в устойчивом порядке, охват и ограничения |
| 7 | Открыть замечание | видны тип, проблема, причина, вопрос, приоритет с обоснованием и переход к процитированному фрагменту |
| 8 | Отправить один вопрос по замечанию | ход отображается как выполняющийся, отправка следующего недоступна с указанием причины |
| 9 | Дождаться ответа | видны текст ответа, вид ответа и предложенная резолюция при её наличии; решение остаётся «не рассмотрено» |
| 10 | Сохранить решение с обоснованием | решение видно с автором и временем; отчёт не изменился |

## Обязательные негативные проверки

| Проверка | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| Неудачное завершение | `run-failed` | причина, признак возможности повтора, отчёт не предлагается |
| Частичный отчёт | `report-partial` | признак неполного охвата, пропуски с причинами, статусы всех источников |
| Ход в генерации | `dialogue-generating` | следующий ход недоступен, причина названа |
| Ошибка хода | `dialogue-failed` | причина показана, повтор доступен без повторного ввода вопроса |
| Конфликт решения | `decision-conflict` | актуальное значение показано, введённый текст сохранён, повтор одним действием |
| Конфликт диалога | `dialogue-conflict` | то же для отправки хода |
| Чужой идентификатор | `not-found` | «не найдено» без упоминания прав доступа |
| Неудачное извлечение | `document-extraction-failed` | запуск запрещён с причиной и предложением загрузить документ в другом виде |
| Пустой отчёт | `empty-report` | явное сообщение «замечаний не найдено» вместе с охватом и ограничениями |
| Долгий запуск | `run-stalled` | через 15 минут без смены состояния появляется предупреждение с длительностью, опрос продолжается |

## Проверка неизменяемости отчёта

1. Открыть отчёт, запомнить сводку, состав замечаний и идентификатор отчёта.
2. Сохранить решения по нескольким замечаниям и провести ход диалога.
3. Повторно открыть отчёт: сводка, состав и формулировки замечаний, охват, ограничения и сведения о происхождении результата совпадают с шагом 1.

## Проверка доступности

Пройти весь smoke-сценарий только с клавиатуры, без мыши. Каждое поле имеет видимую подпись; состояния запуска, замечания, решения и хода различимы текстом или знаком, а не только цветом.

## Тесты

```bash
npm run typecheck
npm run test           # Vitest + Testing Library
npm run test:e2e       # Playwright против MSW
```

## Переключение на реальный backend

Когда backend отдаёт данные по тому же контракту, приложение запускается с базовым URL реального API и отключённым worker моков. Код компонентов и hooks при этом не меняется — расхождение считается ошибкой реализации, а не поводом править локальный тип (принципы I и III).

## Что не проверяется этим документом

Продуктовая ценность ревью, полезность замечаний и экономия времени аналитика. Проверки выше подтверждают поведение интерфейса, а не результаты продуктовых гипотез.
