# Контракты web-контура

**Дата**: 2026-09-04. **План**: [../plan.md](../plan.md).

Публичный HTTP-контракт этой фичей не создаётся и не изменяется. Единственный источник истины — [contracts/review-platform/v1/openapi.yaml](../../../contracts/review-platform/v1/openapi.yaml) в интеграционной ветке. Документы в этом каталоге описывают только то, что принадлежит web-контуру: маршруты приложения, соответствие состояний контракта состояниям интерфейса, правила генерации клиента и сценарии моков.

## Порядок изменения внешнего контракта

Если при реализации обнаружено несоответствие между `openapi.yaml` и потребностями интерфейса, действует принцип I раздела [«Принципы реализации»](../../../AGENTS.md):

1. Не править локальный тип и не обходить несовпадение в коде web.
2. Оформить отдельный PR в `codex/002-target-review-platform`, обновив в одном коммите `openapi.yaml`, JSON Schema, примеры и `CHANGELOG.md`.
3. После merge подтянуть один контрактный коммит в обе реализационные ветки и перегенерировать клиент.

Изменение контракта не совмещается в одном PR с крупной реализацией.

## Что web не делает

- Не читает файлы PoC и не разбирает `review-output.v1` напрямую — только HTTP-ресурсы.
- Не хранит и не показывает секреты провайдера модели.
- Не содержит экранов входа, регистрации, ролей и выбора рабочего пространства.
- Не изменяет опубликованный отчёт ни решением, ни диалогом.
