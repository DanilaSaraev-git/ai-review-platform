# Контракт генерации клиента

**Дата**: 2026-09-04. Основание: принцип II раздела [«Принципы реализации»](../../../AGENTS.md), [порядок параллельной разработки](../../../architecture/parallel-development.md).

## Источник и выходы

Единственный вход генерации — [contracts/review-platform/v1/openapi.yaml](../../../contracts/review-platform/v1/openapi.yaml). Конфигурация `apps/web/orval.config.ts` порождает в `apps/web/src/api/generated/`:

| Выход | Содержимое | Кто использует |
| --- | --- | --- |
| Типы | все DTO контракта | весь прикладной код |
| HTTP-клиент | функции операций поверх собственного mutator | query hooks |
| Query hooks | hooks TanStack Query для операций | features |
| MSW handlers | базовые обработчики операций | сценарии моков |

Собственный mutator живёт в `apps/web/src/api/http-client.ts` и не генерируется. Он отвечает за базовый URL, заголовок `Idempotency-Key` для создающих операций, разбор `application/problem+json` и приведение ошибок к внутреннему типу.

## Правила

1. Ручные копии DTO запрещены. Любой тип запроса или ответа импортируется из `src/api/generated/`. Локальными остаются только типы состояния интерфейса, не пересекающиеся с контрактом.
2. Сгенерированные файлы не коммитятся: `src/api/generated/` внесён в `.gitignore`. `package-lock.json`, наоборот, коммитится.
3. Генерация выполняется скриптом `npm run api:generate` и является предусловием сборки, типизации, тестов и E2E.
4. CI перегенерирует клиент и проверяет отсутствие diff. Diff означает ручную правку сгенерированного файла или расхождение с контрактом — и то, и другое исправляется в источнике, а не в выходе.
5. Несовпадение контракта с потребностью интерфейса не обходится локальной правкой типа. Оно оформляется контрактным PR в `codex/002-target-review-platform` (см. [README.md](README.md)).
6. Пакетный менеджер — npm. Все зависимости фиксируются точными версиями, без диапазонов.

## Порядок при обновлении контракта

1. Подтянуть контрактный коммит из интеграционной ветки.
2. Выполнить `npm run api:generate`.
3. Прогнать типизацию и тесты; расхождения устранять в прикладном коде, а не в сгенерированных файлах.
4. Обновить сценарии MSW, если изменились примеры (см. [msw-scenarios.md](msw-scenarios.md)).

## Проверки в составе Definition of Done

- Генерация проходит без ручных правок, повторная генерация не даёт diff.
- Типизация TypeScript проходит.
- В коде продукта нет объявлений, дублирующих DTO контракта.
- `package-lock.json` присутствует в коммите, `src/api/generated/` — отсутствует.
