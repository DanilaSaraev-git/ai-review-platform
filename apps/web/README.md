# Numbat — веб-интерфейс

Интерфейс предварительного ревью ТЗ на данные для аналитика: загрузка документа,
фоновая проверка, разбор адресных замечаний, диалог по замечанию и решение
человека.

Спецификация, план и задачи: [`specs/005-web-review-ui/`](../../specs/005-web-review-ui/).
Контракт HTTP: [`contracts/review-platform/v1/`](../../contracts/review-platform/v1/).

## Требования

- Node.js 24.20.0 LTS (проект собирается и на 22.21.0, целевой версией остаётся 24.20.0)
- npm

## Установка и генерация клиента

```bash
npm ci
npm run api:generate
```

Генерация обязательна перед сборкой, типизацией и тестами: каталог
`src/api/generated/` не хранится в репозитории. Единственный источник — 
`contracts/review-platform/v1/openapi.yaml`. Ручные копии DTO запрещены; если
повторный запуск генерации даёт diff, значит сгенерированный файл правили
руками либо он разошёлся с контрактом — исправление вносится в источник
(принцип II, [contracts/orval.md](../../specs/005-web-review-ui/contracts/orval.md)).

## Запуск против моков

Сценарий обязателен: без `VITE_MSW_SCENARIO` worker моков не запускается и
приложение обращается к реальному backend.

```bash
VITE_MSW_SCENARIO=happy-path npm run dev          # основной сценарий
VITE_MSW_SCENARIO=report-partial npm run dev      # частичный отчёт
VITE_MSW_SCENARIO=decision-conflict npm run dev   # конфликт ревизии решения
```

В PowerShell переменная задаётся отдельной командой:

```powershell
$env:VITE_MSW_SCENARIO='happy-path'; npm run dev
```

Доступные сценарии перечислены в
[contracts/msw-scenarios.md](../../specs/005-web-review-ui/contracts/msw-scenarios.md)
и собраны в `src/mocks/scenarios/`. Все данные синтетические: материалы кейса
в интерфейс не переносятся (принцип VI).

## Проверки

```bash
npm run typecheck
npm run lint
npm test          # Vitest + Testing Library
npm run test:e2e  # Playwright против MSW
npm run test:e2e:demo # Production-сборка /demo/ с синтетическим runtime-пакетом
npm run build
```

Playwright запускает отдельный сервер MSW на порту 5175 и не переиспользует
открытый интерфейс с реальным backend. Другой порт задаётся через `VITE_E2E_PORT`.
Проверка деморежима использует отдельную production-сборку на порту 5176.

## Переключение на реальный backend

Для уже работающего локального API можно открыть отдельный экземпляр интерфейса:

```bash
VITE_API_PROXY_TARGET=http://127.0.0.1:18000 npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

Для удалённого API:

```bash
VITE_API_BASE_URL=https://<host>/api npm run dev
```

Если `VITE_MSW_SCENARIO` не задан, worker моков не запускается и приложение идёт
в реальный API. Меняется только транспорт: компоненты, hooks и DTO остаются
теми же (принцип III).

## Структура

| Каталог | Назначение |
| --- | --- |
| `src/api/` | mutator, разбор ошибок, правила опроса, ключи кэша, идемпотентность |
| `src/api/generated/` | Orval: типы, клиент, query hooks, MSW handlers (не коммитится) |
| `src/app/` | провайдеры, маршруты, каркас страницы |
| `src/features/new-review/` | подготовка запуска и повтор сохранённой версии: документ, контекст, профили |
| `src/features/document-cycle/` | документы, история версий, сопоставление замечаний, подтверждение исправлений |
| `src/features/review-run/` | список запусков и наблюдение за состоянием |
| `src/features/review-report/` | отчёт, замечания, охват, источники |
| `src/features/finding-decision/` | решение человека и конфликт ревизии |
| `src/features/finding-dialogue/` | диалог по одному замечанию |
| `src/components/document-viewer/` | просмотр PDF и текста, переход к фрагменту |
| `src/mocks/` | сценарии и синтетические фикстуры |
| `e2e/` | сквозные проверки Playwright |

## Интерфейс MVP

Рабочее место построено вокруг полного исходного документа и панели разбора.
Основной документ сохраняется при переходах между состоянием запуска, отчётом,
замечаниями, диалогом и решениями; переключение вкладок сохраняет его прокрутку.
Выбор замечания прокручивает документ к сопоставленной цитате. Цитата из контекста
не заменяет основной документ. PDF отображается целиком, со всеми страницами.
На desktop панели остаются рядом; на узком экране складываются по вертикали,
с отдельной прокруткой и без горизонтального переполнения страницы.
Загруженный документ также остаётся открыт при подготовке новой проверки.
Контекст запуска, ограничения, источники и параметры
выполнения раскрываются рядом с местом использования. В навигации показаны
доступные разделы и переход между рабочим сервисом и деморежимом.

Рабочий сервис и отдельный `/demo/` используют общие компоненты Numbat. Деморежим
показывает подготовленный пример, сохраняет решения в текущей вкладке и явно
обозначает источник результатов. Его API и service worker изолированы от рабочего
сервиса. Приватные материалы подключаются на сервере через runtime mount и не
включаются в исходники или сборку; детали — в
[руководстве выпуска](../../docs/operations/deployment.md).

Оболочка Numbat использует бордовую навигацию, нейтральные поверхности и локальный
шрифт Onest. Шрифт не требует запросов к внешнему CDN; лицензия находится в
`public/fonts/OFL.txt`.

Проверка адаптивной композиции входит в `e2e/visual-layout.spec.ts` для ширины
1440, 1280 и 390 пикселей. Тест сохраняет синтетические screenshots в каталог
результатов Playwright для ручной визуальной оценки; screenshots не коммитятся.

## Цикл документа и выгрузка

[SpecKit 009](../../specs/009-document-review-cycle/spec.md) добавляет раздел
«Документы» (`/documents`), карточку с версиями и проверками, загрузку новой
версии отдельным действием и повтор сохранённого запуска без загрузки.
Форма повтора предзаполняет документ, контекст, профиль проверки и модель.
Если прежний профиль недоступен, интерфейс показывает замену до явного запуска.
Новое открытие формы создаёт новое намерение; сетевой повтор внутри формы
сохраняет ключ идемпотентности.

«Изменения замечаний» в опубликованном отчёте показывает неизменную базу
сравнения, повторённые/новые/исчезнувшие/сомнительные/непроверенные/вернувшиеся
проблемы. Прежняя оценка переносится только при разрешённом сервером переносе
и нетронутом текущем решении (`revision == 0`). Явный сброс оценки имеет
приоритет. Связи один-к-одному и подтверждения исправления редактируются
отдельно; конфликт ревизии сохраняет пояснение и требует обновить состояние.
Исходник выбранной проверки остаётся открыт.

«Скачать PDF» запрашивает полный снимок выбранной проверки с текущими статусами,
независимо от экранного фильтра. Файл создаёт сервер; браузер показывает
ошибку выгрузки и разрешает повтор. В подготовленном `/demo/` новые разделы
цикла и серверная выгрузка пока не представлены.

Полный синтетический пример доступен через `VITE_MSW_SCENARIO=document-cycle`.
Сценарий использует Orval handlers и канонические synthetic examples;
проверяется в `e2e/document-cycle.spec.ts`, включая сохранение исходника,
ручное исправление связи, перезагрузку, PDF и ширину 390 px. Для локальной
проверки всего Vitest-набора можно ограничить параллелизм: `npm test -- --maxWorkers=4`.
